# FOX 实景商业游戏 · 产品方案 / 设计文档 v2 / 开发计划

> 版本：v2（v1 产品方案 → 红队评审 → v2 完善稿）
> 日期：2026-09-18 ｜ 仓库：`workroom-fox`（试验田）
> 定位：把「懂汇报的狐狸先生」从"交互与影音汇报试验田"推进为**实景商业游戏**
> ——客户像玩一款经营大作一样经营真门店，而每一步都对应真实的钱、真实的人审、真实的回执。

---

## 1. 一句话产品

**你玩的不是模拟经营，你玩的是你自己的店。**

游戏里的每一项进度、每一枚成就、每一次 Boss 击破，都由真实经营行为解锁：
派活 → 真实线程；拍板 → 真实审批；交付 → 真实回执；夜班 → 真实巡检；
营收 → 真实订单。玩得好 = 店真的在变好；店变好 = 账上的钱真的多了。

## 2. 为什么"游戏化"在这里不是装饰

传统 SaaS 的问题是：**你不知道今天该干什么，也不知道干了有没有用。**
行业版客户（20–50 间房的单体酒店、5–20 间房的民宿）连"日会"都开不全，
更不会给自己定 KPI。游戏化在这里解决的是三件非常具体的事：

| 问题 | 游戏化给的东西 | 可验证口径 |
|---|---|---|
| 不知道下一步做什么 | 主线章节 + 每日任务（永远只有 1 件"下一件"） | `nextUp` 命中率：HUD 曝光后 24h 内该里程碑完成率 |
| 干了没反馈，三天就荒废 | 即时反馈（事件→动效/字幕/语音）+ 连续经营 streak | 次周留存、streak≥3 天数占比 |
| 不知道 AI 到底有没有替我挣钱 | 赛季营收里程碑 + Boss 攻坚（差评/空房） | 赛季营收达成率、差评响应时长、出租率回升幅度 |

**红线**：游戏层不给权限、不改围栏、不写账本事实、不产生第二账本。
它只做"把真实经营翻译成看得见的进度"。

## 3. 3A 视角的七要素（设计基线）

以单机 3A 经营大作（如《文明》《模拟城市》《星露谷》的可玩性来源）为参照，
本方案把七要素逐一落到可实现的工程对象上：

| 要素 | 3A 做法 | FOX 落地 | 当前状态 |
|---|---|---|---|
| **核心循环** | 采集→建造→升级→再采集 | 派活→拍板→交付→沉淀→下一件（Quest 循环） | 已有（questline + runtime loop） |
| **进度系统** | 等级/章节/科技树 | 赛季章节（4 章 14 里程碑）+ XP + 成就 | 本轮实现（campaign） |
| **反馈系统** | 即时音画反馈 | 事件→字幕/语音/动效/3D 舞台（M1 视听觉醒） | 事件已产出，动效待接（M2-c） |
| **经济系统** | 资源→产出→再投资 | **只映射真实营收**；不做虚拟币、不做付费加速 | 数据未接入（M2-b） |
| **社交/协作** | 帮派/联机 | 多门店团队协作、审批会签、榜单（隐私可选） | 待做（M3） |
| **叙事与世界观** | 主线剧情 | 「狐狸先生的汇报舞台」：每章一段汇报演出 | 剧本已有骨架，演出待做（M2-c） |
| **失败与重来** | 失败可读、可重来 | Boss 攻坚（差评风暴/空房危机）+ 断签不清零历史最佳 | 本轮实现（campaign Boss） |

## 4. 世界观与角色（叙事层）

- **玩家**：董事长/店主（真人，唯一有权限做高风险决断的人）。
- **主角 NPC**：狐狸先生（本仓既有形象，SVG + CSS，六态）。
  新版定位从"引导员"升级为**你的合伙人**：会在章节开篇做汇报演出、在 Boss 出现时报警、
  在击破后开复盘会。
- **团队**：数字员工班组（收益定价官 / 口碑公关官 / 财务司库官 …），
  他们的能力成长来自真实的技能考试与夜班战绩（不允许"充值变强"）。
- **反派**：不是虚构怪物，而是**真实的经营异常**——差评风暴、空房危机、渠道价格战、
  夜班积压。Boss 的战报就是经营报表。

## 5. 核心循环（Core Loop，v2 定稿）

```
            ┌──────────────────────────── 赛季（Season）────────────────────────────┐
            │                                                                        │
  打开经营主页 → 看到"下一件"（nextUp） → 派活/拍板/处理差评 → 真实回执落账
            ↑                                        ↓
      反馈：动效+字幕+语音 ← 赛季事件（里程碑/每日任务/Boss/连续经营）← 事实聚合
            │                                        ↓
            └──────────── 章节推进 → 新章节开篇演出 → 赛季营收目标 ←─ 营收（真实）─┘
```

关键设计决定（v2 相比 v1 的改动）：

1. **v1** 想做"每日任务 + 随机奖励箱" → **v2 删除随机奖励**：一切奖励确定性、可预期
   （避免可变比率强化带来的类赌博机制，也避免客户算不清）。
2. **v1** 想引入"游戏币" → **v2 删除游戏币**：任何虚拟货币都会诱发"刷币即刷业绩"，
   直接威胁本仓"不编造事实"的纪律。经济系统只保留"真实营收里程碑"。
3. **v1** 的里程碑允许由前端点击"我做到了" → **v2 全部改为事实驱动**，
   前端只能"确认目标"这类主观项，且必须留痕。
4. **v1** 的 streak 按"打开页面"计算 → **v2 改为"当天有真实经营动作"**
   （派活/拍板/交付/沉淀/夜班/差评处置/营收增量任一），并保留历史最佳。

## 6. 红队评审（自我完善：12 个风险与对策）

| # | 风险 | 结论 | 对策（已落到代码/计划） |
|---|---|---|---|
| 1 | 成瘾性：连续登录奖励诱导超时停留 | 中 | 不做"错过就消失"的惩罚性 FOMO；streak 断签只归零不给惩罚；不做倒计时弹窗 |
| 2 | 赌博机制：随机箱/概率抽奖 | 高 | **明确禁止**；奖励全部确定性；代码层无随机奖励 API |
| 3 | 虚假进度：前端点击即可通关 | 高 | 里程碑只认 `CampaignFacts`（服务端事实）；未接入的事实按 0 = 未知，不触发 |
| 4 | 双账本：前端 XP 与后端 roster 不一致 | 高 | campaign 只发放"本层奖励经验"用于展示，等级与总 XP 仍以 roster/questline 为唯一事实源 |
| 5 | 隐私：排行榜泄露门店经营数据 | 中 | M3 榜单默认关闭，仅同租户内、仅匿名化指标、可整体关闭 |
| 6 | 误导：营收未接入却显示"0" | 中 | HUD 显式显示「未接入」，不显示假数字；里程碑不点亮 |
| 7 | 权限越界：游戏层给"特权" | 高 | 游戏层不产生任何权限；高风险动作仍走围栏 + 人审 |
| 8 | 性能：每次事实变化全量重算 | 低 | 纯函数 + 事实指纹依赖；单次 tick O(里程碑数)，无网络、无 DOM |
| 9 | 可测性：UI 才有的逻辑无法回归 | 中 | 全部核心逻辑在 `campaign.ts`（纯函数，30 条单测）；UI 只做展示 |
| 10 | 时区：跨日判定错位 | 中 | 经营日固定 `Asia/Shanghai`（+480），与定时任务/夜班同口径，含 UTC 边界单测 |
| 11 | 多门店：一店一套进度还是共享 | 中 | M3：进度按 workspace 隔离，跨店只看"集团赛季进度"，不混算单店指标 |
| 12 | 移动端/降级：小屏放不下 | 低 | HUD 默认仅 `sm:` 以上显示，可折叠；不阻塞任何业务按钮 |

## 7. 章节与 Boss（第一赛季内容）

章节（`campaign.config.ts`）：

| 章 | 主题 | 通关条件（全部为真实事实） |
|---|---|---|
| 第一章 · 开张 | 班底立起来 | 定目标 + 首派活 + 首拍板 + 首批交付 |
| 第二章 · 稳住基本盘 | 夜班与口碑 | 沉淀 5 + 夜班 3 + 处理差评 3 + 交付 5 |
| 第三章 · 起量 | 节奏换营收 | 赛季营收 ¥5,000 + 拍板 10 + 交付 15 |
| 第四章 · 飞轮 | 自转 | 沉淀 20 + 夜班 10 + 赛季营收 ¥20,000 |

Boss（真实异常攻坚，出现与击破都只认事实）：

| Boss | 出现条件 | 击破条件 | 奖励 |
|---|---|---|---|
| 差评风暴 | 待处理差评 ≥3 | 待处理差评 ≤1 | 成就「风暴平息」+25 XP |
| 空房危机 | 出租率 1%~49% | 出租率 ≥65% | 成就「满房反击」+30 XP |

> 未知即未知：出租率未接入时填 0，不满足"≥1"下界 → 不会凭空出现 Boss。

## 8. 开发计划（里程碑 / 验收标准 / 测试方式）

| 里程碑 | 内容 | 验收标准 | 测试方式 | 状态 |
|---|---|---|---|---|
| **M2-a 经营主线引擎** | `campaign.ts` + 配置 + 单测 + HUD + P0 接线 | 30 条单测全绿；typecheck 通过；HUD 在桌面端可见可折叠 | vitest + tsc + 真实页面截图 | ✅ 本轮完成 |
| **M2-b 经营事实聚合** | 服务端 `campaign.facts` 聚合（营收/夜班/沉淀/差评/出租率），走真实表与事件账本 | 事实与报表口径一致（抽样比对）；未知字段返回 `null` 而非 0 | 真库集成测试 + 抽样比对脚本 | ⏳ 下一轮 |
| **M2-c 演出层** | 章节开篇汇报演出（狐狸先生 + 3D 舞台 + 语音 + 字幕）、里程碑动效、Boss 警报音 | 演出可跳过、`prefers-reduced-motion` 降级；不阻塞业务 | 截图 + 录屏 + 手动核对 | ⏳ |
| **M2-d 服务端进度** | `campaign_progress` 表 + RLS，替换 localStorage | 跨设备续播；RLS 越权返回空；迁移可回滚 | 真库 RLS 测试 + 迁移回滚演练 | ⏳ |
| **M3-a 多店协作** | 集团视角赛季进度、门店间榜单（默认关闭） | 单店指标不泄露；可在租户级一键关闭 | 权限测试 + 越权用例 | ⏳ |
| **M3-b 赛季复盘** | 赛季结束生成复盘报告（含错过项与原因） | 报告可追溯到每个里程碑的事实来源 | 报告与事件账本对账 | ⏳ |

## 9. 本轮实现范围（M2-a）

代码位置：

```
apps/web/src/extensions/fox/campaign/          （行业扩展边界内：extensions/**，UI 升级不判分叉）
  campaign.ts          纯逻辑：赛季状态机 / 事实驱动 / 每日任务 / streak / Boss / 持久化（无 React/DOM）
  campaign.config.ts   内容：第一赛季 4 章 14 里程碑 + 4 每日任务 + 2 Boss + 成就名
  campaign.test.ts     30 条单测（含时区边界、未知不触发、幂等、断签、版本脏读）
  useCampaign.ts       React 容器：localStorage 持久化 + 事实驱动 + 埋点
  CampaignHud.tsx      常驻面板：赛季进度 / 下一件 / 每日任务 / 连续经营 / Boss / 成就
apps/web/src/extensions/fox/HomeQuestlineSlot.tsx   挂载点（首日上岗插槽内与 QuestlineHud 成对；受管 P0 零改写）
```

**未接入（诚实边界）**：`settled / nightRuns / handledNegativeReviews / revenueCny /
openNegativeReviews / occupancyPct` 目前由 P0 明确填 0（未知），
因此第二章及以后的里程碑与 Boss 在本轮**不会**点亮——HUD 会显示「未接入」而不是假数字。
接入工作即 M2-b。

## 10. 不做什么（Negative List）

1. 不做虚拟货币、随机奖励箱、抽卡、概率掉落；
2. 不做"错过就永久失去"的惩罚性机制；
3. 不给任何游戏奖励绑定真实权限（含审批、群发、发布、资金）；
4. 不用游戏进度掩盖经营事实（不把"未接入"显示成 0，不把"跳过"显示成"完成"）；
5. 不在试验田外扩散：本章节内容与 HUD 属于 `workroom-fox`，
   抽象后的通用能力（事实聚合、进度引擎）成熟后再评估是否上收到基座。
